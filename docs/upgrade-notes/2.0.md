# Upgrade to Export 2.0

This document lists the backward incompatible changes of the Export module 2.0 and what has to be done about them.

The Export module 2.0 requires AtroCore 3.0. The modules extending the Export module - Export Remote File, Export Database, Export HTTP, Synchronization - require the Export module 2.0.

## Export feed types are subtypes

Every export feed type is a subtype of `ExportFeed`: `ExportFeedTypeSimple` of the Export module, `ExportFeedTypeFtp` of the Export Remote File module, `ExportFeedTypeDatabase` of the Export Database module and `ExportFeedTypeHttpPro` of the Export HTTP module. The values of `type` are not changed. The subtypes are described in the upgrade notes of AtroCore 3.0.

- **`ExportFeed` keeps everything shared by the types**: the name, the type, the entity, the file format and its settings, the template, the locale, the content language, the sorting, the limit, the jobs, the headers of the HTTP request, the sheets and the relations. The `data` field keeps `where`, `whereData` and `withDeleted`.
- **The settings of the file format are columns of the export feed**: `entity`, `csvFieldDelimiter`, `csvTextQualifier`, `convertCollectionToString`, `delimiter`, `convertRelationsToString`, `fieldDelimiterForRelation`, `emptyValue`, `nullValue`, `markForNoRelation`, `markForUnlinkedAttribute`, `exportByMaxDepth`. They were stored in `data.feedFields` before; the upgrade moves them.
- **The settings of a type are fields of its subtype**: `fileNameMask` of `simple`, `connection` and `staticFilePath` of `ftp`, `connection` of `database`, `connection`, `httpMethod`, `httpUrl`, `exportHttpValidator`, `processResponse` and `processResponseFormatter` of `httpPro`. The upgrade moves them from the columns and from `data.feedFields`. The relation of a connection to its export feeds (`Connection.exportFeeds`) is removed, the export feeds of a validator (`ExportHttpValidator.exportFeeds`) are the HTTP export feeds.
- **The REST API creates an export feed via its type**, e.g. `POST /api/ExportFeedTypeSimple`; `POST /api/ExportFeed` is not available. The routes of the export feed (`exportFile`, `addFields`, `addAttributes` and the others) take the ID of the export feed record.

## Behavior changes

- **An export feed can be configured for a subtype**, e.g. `AttributeTypeInt`: the list of the entities of the export feed contains the subtypes. An export feed of an entity with subtypes exports the fields of the supertype only, an export feed of a subtype exports the fields of the supertype and of the subtype.

## Custom code

- **`Export\Services\AbstractService` is removed.** It was not used by the export types.
- **`GET /api/ExportFeed/syncErrorStatistics` is replaced by `GET /api/Dashlet/DataSyncErrorsExport`.** The data of the dashlet is provided by `Export\Dashlets\DataSyncErrorsExport`, set as `className` in `metadata/dashlets/DataSyncErrorsExport.json`; `Export\Services\DataSyncErrorsExportDashlet` and `Export\Services\AbstractDashletService` are removed. The dashlets are described in the upgrade notes of AtroCore 3.0.
- **`ExportFeed::getFeedField()`, `getFeedFields()` and `setFeedField()` are removed.** The settings of the file format are read from the export feed, `$feed->get('entity')`, the settings of a type from the subtype record, `$feed->getSubtype()->get('httpUrl')`.
- **The export types keep reading the settings from the feed data.** `ExportFeed::prepareFeedData()` puts the settings of the file format and of the type into the feed data and into its `data`, e.g. `$this->data['feed']['httpUrl']` and `$this->data['feed']['connectionId']`.
- **A module adds an export type as a subtype**: the scope `ExportFeedType<Type>`, its entityDefs, the detail and relationships layouts and the class of the type registered as the service `ExportType<Type>`, the file formats of the type in `app.exportTypes`. The subtype gets the views and the panels of `ExportFeed`. A module adding fields to `ExportFeed` for its type has to move them to its subtype; its `ExportFeedLayout` listener for the detail layout is replaced by the layout of the subtype. A module changing the fields of `ExportFeed` does it in the `loadData` method of its metadata listener, so that the subtypes get the changes.
- **The configurator items are sorted by `PATCH /api/entityRelationSortOrder`** of the core with `entityName` `ExportFeed` and `link` `configuratorItems`. `PATCH /api/ExportConfiguratorItem/{id}` does not handle `_itemId` and `_previousItemId` anymore; `previousItem` of the item keeps placing it after another item.
